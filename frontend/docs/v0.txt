# v0에 그대로 붙여넣을 프롬프트

다음 요구사항으로 프론트엔드를 만들어줘. 백엔드와 실제 데이터셋은 아직 없으므로, API 호출 없이 정교한 목데이터로 동작하는 **프론트엔드 데모**를 구현해줘.

## 프로젝트

- 서비스명: **Arcane Arsenal**
- 한 줄 설명: 이미지와 자연어 조건을 결합해 2D 판타지 무기 에셋을 찾는 멀티모달 검색 서비스
- 핵심 사용자: 게임 제작자·아트 디렉터가 참고 이미지와 자연어 조건을 사용해 원하는 무기 에셋을 빠르게 찾는다.
- 구현: Next.js(App Router) + TypeScript + Tailwind CSS + shadcn/ui + lucide-react. 차트는 Recharts를 사용한다.
- 언어: 인터페이스의 모든 문구는 자연스러운 한국어로 작성한다. 코드 식별자는 영어로 작성한다.
- 범위: **UI와 목데이터만 구현한다.** 실제 이미지 업로드, 로그인, DB, 벡터 검색, 외부 API 연결은 하지 않는다.

## 디자인 방향

- 발표용 검색 도구답게 정보 밀도가 높되 복잡하지 않은 데스크톱 우선 대시보드로 디자인한다. 반응형에서는 필터 패널이 Sheet/Drawer로 바뀌어야 한다.
- 배경은 차가운 거의-흰색, 패널은 흰색, 텍스트는 진한 청회색으로 한다. 포인트 컬러는 차분한 보랏빛(마법/선택 상태)과 불·얼음·번개 등의 의미색만 사용한다. 과한 판타지 장식, 금색 테두리, 글래스모피즘, 과도한 그라데이션은 피한다.
- 폰트는 Inter 또는 시스템 sans-serif 한 가지를 사용한다. 카드 모서리는 12px 이하, 접근 가능한 대비와 선명한 키보드 focus 상태를 적용한다.
- 결과 카드의 이미지에는 실제 외부 이미지를 의존하지 말고, 서로 구분되는 무기 목업 썸네일(인라인 SVG 또는 CSS 기반 placeholder)을 사용한다. 각 썸네일은 검/도끼/활/지팡이/창/방패처럼 한눈에 구분되고 색상·속성이 달라 보여야 한다.
- 기본 상태가 실제로 작동하는 제품처럼 보이게 한다. 버튼, 슬라이더, 필터, 정렬, 탭은 모두 클라이언트 목데이터를 기준으로 상호작용한다.

## 화면 구조

한 개의 앱 셸 안에 `검색`과 `성능 평가` 두 페이지/탭을 제공한다. 첫 화면은 검색 탭이다.

### 1. 공통 앱 셸

- 상단 고정 헤더: 좌측 심볼과 `Arcane Arsenal`, 중앙/우측에 `검색`, `성능 평가` 탭. 우측에는 `목데이터 데모` 배지와 정보 아이콘 툴팁(`실제 검색 API 연결 전 UI 시연용 데이터입니다.`).
- 검색 화면은 좌측 필터 사이드바(약 280px) + 우측 메인 콘텐츠의 2열 레이아웃이다.
- 모바일/태블릿에서는 사이드바를 `필터` 버튼으로 열리는 Drawer로 바꾸고, 결과 그리드는 1~2열로 자연스럽게 축소한다.

### 2. 검색 입력 영역

메인 상단에 제목 `어떤 무기를 찾고 있나요?`와 설명 `텍스트, 참고 이미지, 또는 두 조건을 함께 사용해 보세요.`를 둔다.

- 자연어 검색창: 큰 입력창, placeholder는 `예: 푸른 마법이 깃든 판타지 양손검`. 돋보기 아이콘, Enter로 검색 실행.
- 예시 질의 칩 3개: `푸른 마법이 깃든 양손검`, `금색 불 속성 무기`, `픽셀아트 단검`.
- 이미지 업로드: 드래그앤드롭 가능한 컴팩트한 영역. 업로드 전에는 `참고 이미지 추가 (선택)`과 지원 형식 안내를 표시한다. 클릭하면 파일 선택 UI를 열고, 파일을 선택하면 실제 업로드 대신 해당 파일명과 목업 미리보기, 제거 버튼을 보여 준다.
- 이미지와 텍스트가 모두 입력되면 바로 아래에 `결합 검색` 배지를 표시한다. 텍스트만/이미지만 입력된 경우에도 해당 검색 모드를 분명히 보여 준다.
- `검색하기` 기본 버튼, `초기화` 보조 버튼을 둔다. 검색 클릭 시 350~500ms 정도 결과 영역의 skeleton을 보여 준 뒤 목데이터 결과를 갱신한다.

### 3. 이미지·텍스트 가중치 UI

입력 영역 아래에 접을 수 없는 명확한 제어 패널을 만든다.

- 제목: `검색 기준 조절`
- 설명: `참고 이미지의 형태를 유지할수록 이미지 비중을 높이세요.`
- 이미지 가중치 / 텍스트 가중치를 합계 100%로 보여 주는 단일 range slider. 기본값은 이미지 60%, 텍스트 40%.
- 좌측 라벨 `이미지 우선 · 형태 유지`, 우측 라벨 `텍스트 우선 · 색상·속성 반영`.
- 슬라이더 값을 바꾸면 두 수치와 `현재 설정: 이미지 60% + 텍스트 40%`가 즉시 갱신되고, 결과 정렬도 약간 달라지는 것처럼 목데이터를 재정렬한다.
- 도움말 툴팁: `실제 서비스에서는 이미지·텍스트 임베딩 가중합과 메타데이터 재정렬을 함께 사용합니다.`

### 4. 속성 필터 사이드바

제목은 `속성 필터`, 상단에 `초기화` 텍스트 버튼과 현재 선택 개수 배지를 둔다. 각 필터는 접을 수 있고 다중 선택 가능한 체크박스/칩으로 제공한다.

- 무기 종류: 검, 도끼, 창, 활, 지팡이, 방패
- 주요 색상: 금색, 은색, 검은색, 붉은색, 푸른색, 녹색
- 속성: 불, 얼음, 번개, 독, 암흑, 신성, 무속성
- 세계관 스타일: 중세, 고딕, 엘프, 오크, 마법
- 형태: 한손, 양손, 장검, 단검, 곡선형, 대형
- 희귀도: 일반, 희귀, 전설
- 시각 스타일: 픽셀아트, 일러스트, 아이콘

필터를 적용하면 결과 수, 선택된 필터 칩, 결과 카드가 즉시 변한다. 결과가 없을 때에는 `선택한 조건과 일치하는 에셋이 없습니다.`와 `필터 초기화` 버튼을 보여 준다.

### 5. 검색 결과 대시보드

검색 영역 아래에 결과 대시보드를 구성한다. 단순한 카드 나열이 아니라 “왜 이 결과가 나왔는지”를 읽을 수 있어야 한다.

- 상단 요약 행: `검색 결과 24개`, `평균 유사도 86%`, `조건 일치율 91%`, `응답 시간 142ms`를 간결하게 표시한다. 이 숫자들은 목데이터라는 작은 주석을 함께 둔다.
- 정렬 Select: `종합 점수순`(기본), `유사도순`, `조건 일치순`, `이름순`.
- 활성 필터 칩과 `모두 지우기`를 결과 상단에도 표시한다.
- 4열 반응형 결과 그리드(큰 화면), 2열(태블릿), 1열(모바일). 카드마다 아래를 포함한다.
  - 무기 목업 썸네일과 희귀도 배지
  - 에셋명 예: `Azure Runeblade`, `Flame Greatsword`, `Verdant Longbow`, `Frostbite Spear`, `Stormcaller Staff`, `Obsidian Dagger`
  - 종합 유사도(예: 92%)와 작은 progress bar
  - 태그: 무기 종류, 주요 색상, 속성, 시각 스타일
  - “일치 근거” 2~3개: `이미지 형태 96%`, `푸른색 일치`, `마법 속성 일치`처럼, 체크 아이콘과 함께 표시
  - `자세히 보기`와 `유사 에셋 검색` 버튼
- `자세히 보기`는 오른쪽 Sheet(모바일은 전체 화면)로 연다. 시트에는 큰 목업 이미지, 전체 설명, 메타데이터 표, 점수 분해(벡터 유사도 / 메타데이터 일치 / 최종 점수), 출처, 제작자, 라이선스, 라이선스 확인일, `원본 페이지 열기` 링크 버튼을 제공한다.
- `유사 에셋 검색`을 누르면 해당 에셋을 참고 이미지로 설정한 것처럼 업로드 영역을 바꾸고 결과를 갱신한다.

## 성능 평가 탭

기획 발표에서 검색 품질을 설명할 수 있는 별도 대시보드이다. 실제 계산이 아니라 아래의 정적 목데이터를 Recharts로 시각화한다. 각 카드/차트에는 `평가 목데이터` 배지를 붙인다.

- 상단: 제목 `검색 품질 평가`, 설명 `기준 검색과 멀티모달·메타데이터 재정렬 적용 결과를 비교합니다.`
- KPI 4개: `Recall@5 82.4%`, `MRR 0.71`, `조건 만족률@5 88.0%`, `평균 응답 시간 142ms`.
- 모델 비교 막대 차트: 모델 3개를 비교한다.
  1. `CLIP 벡터 검색`
  2. `이미지+텍스트 가중합`
  3. `가중합 + 메타데이터 재정렬` (강조)
  지표 값: Recall@1 = 42.1 / 49.8 / 58.6, Recall@5 = 67.3 / 75.9 / 82.4, MRR = 0.52 / 0.63 / 0.71, 조건 만족률@5 = 61.2 / 76.5 / 88.0.
- 검색 방식별 성능 차트: 텍스트, 이미지, 이미지+텍스트 3개 방식의 Recall@5를 비교한다(78%, 81%, 88%).
- `필터 적용 전/후` 결과 수와 조건 만족률 변화를 보여 주는 작은 비교 컴포넌트(예: 100개 → 24개, 68% → 91%).
- `성공 사례`와 `개선이 필요한 사례`를 나란히 둔다. 성공 사례는 `검 이미지 + “황금색이며 불 속성으로”`, 실패 사례는 `매우 추상적인 속성 표현`으로 하고, 각각 결과 목업 2장과 짧은 해설을 넣는다.
- 하단에 평가 범위·주의사항: `텍스트/이미지/결합 질의별 100개 평가 질의를 기준으로 한 발표용 예시 수치입니다.`

## 목데이터 요구사항

- 최소 18개 이상의 에셋 객체를 `mockAssets`로 만든다. 각 객체에는 다음 필드가 반드시 있어야 한다.
  `assetId`, `title`, `descriptionKo`, `weaponType`, `colors`, `elements`, `worldStyles`, `forms`, `rarity`, `visualStyle`, `similarity`, `vectorSimilarity`, `metadataMatch`, `source`, `creator`, `sourceUrl`, `license`, `licenseCheckedAt`, `matchReasons`.
- 예시의 `Flame Greatsword`는 다음 데이터를 정확히 포함한다: 검 / 붉은색·검은색 / 불 / 마법·고딕 / 양손·장검 / 전설 / 일러스트 / OpenGameArt / example_creator / CC0-1.0 / 2026-07-20.
- 목데이터는 위의 필터 값 전반을 골고루 포함하고, 필터·정렬·가중치 상호작용에서 결과 차이가 보이도록 한다.
- 검색어를 기준으로 간단한 클라이언트 측 점수 보정 함수를 구현한다. 예를 들어 `푸른`, `불`, `양손`, `픽셀` 같은 키워드가 해당 태그와 맞으면 점수를 높이고, 가중치와 필터에 따라 결과를 재계산한다. 이는 실제 AI 검색이 아니라 시연용 로직임을 코드 주석과 화면 주석으로 명확히 한다.

## 구현 품질 기준

- 의미 있는 aria-label, 키보드 포커스, 버튼의 disabled/loading 상태, 업로드 실패 대신 “지원하지 않는 형식입니다”라는 목업 오류 상태도 포함한다.
- 파일 선택을 취소했을 때, 필터를 초기화했을 때, 검색어·이미지 모두 없는 상태에서 검색 버튼을 눌렀을 때의 UX를 처리한다.
- 초기 상태에는 인상적인 기본 검색 결과를 표시해 빈 화면으로 시작하지 않게 한다.
- 이미지/텍스트 검색, 필터, 정렬, 상세 Sheet, 유사 에셋 검색, 성능 탭을 실제로 클릭해 볼 수 있게 구현한다.
- Dockerfile이나 백엔드 코드는 만들지 않는다. 대신 앱 하단의 작은 `개발 상태` 영역에 `프론트엔드 목업 완료 · API 연동 대기 · Docker 통합 예정`을 표시한다.

완성 후에는 필요한 컴포넌트를 적절히 분리하고, 실행 가능한 단일 Next.js 프론트엔드로 제공해줘.
